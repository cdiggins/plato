# The Cross Product

Two edges of a triangle meet at a vertex. Which way does the face point? Grab the edges as vectors
$\mathbf{a}$ and $\mathbf{b}$. Their **cross product** $\mathbf{a} \times \mathbf{b}$ is a third
vector, perpendicular to both, whose length is the parallelogram area they span, and whose
direction follows the right-hand rule — the same rule Plato's rotations use for positive angles.

That one operation yields surface normals, torque directions, orbital angular notions, and the
signed volume of parallelepipeds (via the scalar triple product). It is also stubbornly
**three-dimensional**: there is no faithful "vector cross product" in 2D or 4D that keeps all the
same properties. Geometric algebra replaces it with a **bivector** — an oriented plane element —
and Plato already names that object.

## The idea

### Algebraic definition

In a right-handed orthonormal basis:

$$
\mathbf{a} \times \mathbf{b} =
\begin{vmatrix}
\mathbf{i} & \mathbf{j} & \mathbf{k} \\
a_x & a_y & a_z \\
b_x & b_y & b_z
\end{vmatrix}
=
(a_y b_z - a_z b_y,\ a_z b_x - a_x b_z,\ a_x b_y - a_y b_x)
$$

### Geometric meaning

$$
\mathbf{a} \times \mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\,\sin\theta\ \hat{\mathbf{n}}
$$

where $\hat{\mathbf{n}}$ is the unit normal given by the right-hand rule when fingers sweep from
$\mathbf{a}$ toward $\mathbf{b}$, and $\theta \in [0,\pi]$ is the unoriented angle between them.

```
        b
       /
      /
     / θ
    ●──────→ a
     \
      ↓ a × b  (out of the a–b plane, right-hand rule)
```

| Property | Fact |
|----------|------|
| Perpendicular | $(\mathbf{a}\times\mathbf{b})\cdot\mathbf{a} = 0$ (same for $\mathbf{b}$) |
| Antisymmetric | $\mathbf{a}\times\mathbf{b} = -(\mathbf{b}\times\mathbf{a})$ |
| Area | $\|\mathbf{a}\times\mathbf{b}\|$ = parallelogram area |
| Parallel → zero | $\mathbf{a}\parallel\mathbf{b} \Rightarrow \mathbf{a}\times\mathbf{b}=\mathbf{0}$ |

Triangle area is half the parallelogram: $\tfrac{1}{2}\|\mathbf{a}\times\mathbf{b}\|$.

### Scalar triple product

$$
(\mathbf{a} \times \mathbf{b}) \cdot \mathbf{c} = \text{signed volume of the parallelepiped}
$$

Positive when $\mathbf{c}$ points to the same side of the $\mathbf{a}$–$\mathbf{b}$ plane as
$\mathbf{a}\times\mathbf{b}$. Orientation tests and tetrahedron volumes use this.

### Why only 3D? (nod to bivectors)

In $n$ dimensions, the natural "plane spanned by two vectors" has $\binom{n}{2}$ independent
components — a **bivector**, not a vector. Only in 3D is $\binom{3}{2} = 3$, so you can pretend the
plane element *is* a vector (its dual). In 2D, $\binom{2}{2}=1$: the cross analogue is a **scalar**
(signed area). In 4D you cannot encode an oriented plane as a single 4-vector the same way.

Geometric algebra keeps the honest object: $\mathbf{a} \wedge \mathbf{b}$ is a bivector. Rotations
are generated by bivectors; Plato's `Bivector3D` stores the three plane components `YZ`, `ZX`, `XY`.

## In Plato

### Cross on geometric 3D vectors

`Vector3D` carries `Cross` among its displacement intrinsics (declared with the vector algebra
hub). `Vector2D` has `Dot` and `Reflect` but **no** `Cross` returning a `Vector2D` — correctly.

```plato
type Vector3D
    implements Vector
{
    X: Number;
    Y: Number;
    Z: Number;
}
```

Usage-shaped:

```
edge0 = p1 - p0                         // Vector3D (via point difference elsewhere)
edge1 = p2 - p0
normal = edge0.Cross(edge1)             // Vector3D, not yet unit
unitN = normal.Normalize
area = 0.5 * normal.Length

// right-handed orthonormal frame from forward + roughUp
right = roughUp.Cross(forward).Normalize
up = forward.Cross(right).Normalize
```

Facing / winding: if vertices are ordered counterclockwise when looking along the intended
outward normal, `edge0.Cross(edge1)` points outward under the right-hand rule.

### Directions and rotations

`10-rotations.plato` ties axes to unit directions:

```plato
type AxisAngle
{
    Axis: Direction3D;
    Angle: Angle;
}
```

Building an `AxisAngle` from two non-parallel vectors often uses cross for the axis:

```
axisVec = from.Cross(to).Normalize
axis = Direction3D(Vector = axisVec)
// angle from acos(clamp(from.Normalize.Dot(to.Normalize))) — separately
```

`Quaternion` / `Rotor3D` compose rotations; they do not replace `Cross` for constructing normals.
Rotating a vector uses `Transform(v, q)`, which preserves the right-handedness of frames built
with `Cross`.

### Bivector3D — the plane itself

```plato
// An oriented plane element in 3D, with components named by the planes they span;
// the generator of 3D rotations in geometric algebra.
type Bivector3D
    implements Value
{
    YZ: Number;
    ZX: Number;
    XY: Number;
}

type Rotor3D
{
    Scalar: Number;
    Bivector: Bivector3D;
}
```

The dual of $\mathbf{a}\times\mathbf{b}$ as a vector is the bivector $\mathbf{a}\wedge\mathbf{b}$
with those plane weights. When you only need "which plane" and "how much area," the bivector is
the clearer noun; when APIs want a normal arrow for shading, `Cross` returns `Vector3D`.

```
// Conceptual pairing (illustrative — no wedge operator declared on Vector3D yet):
//   cross = (cx, cy, cz)  ↔  bivector ≈ Bivector3D(YZ: cx, ZX: cy, XY: cz)
// under the standard Euclidean dual in a right-handed basis
```

### 2D reminder

In the plane, the scalar $a_x b_y - a_y b_x$ plays the "signed area / sine" role. Plato's 2D
rotation types (`Rotation2D`, `Bivector2D` with a single `XY` component, `Rotor2D`) encode planar
orientation without pretending there is a third axis inside `Vector2D`.

## Pitfalls / fine print

**Left-handed engines.** If your host mesh format is left-handed, `Cross` still obeys Plato's
right-hand rule — flip winding or negate normals at the boundary.

**Non-unit results.** `Cross` of two unit vectors is unit only if they are perpendicular. Always
`Normalize` before using as `Direction3D`.

**Degenerate triangles.** Parallel or zero edges → zero cross → normalize fails. Test
`LengthSquared` before building normals.

**Order matters.** `a.Cross(b)` vs `b.Cross(a)` flips the normal and flips winding-sensitive
booleans.

**Cross is not associative.** $(\mathbf{a}\times\mathbf{b})\times\mathbf{c} \neq
\mathbf{a}\times(\mathbf{b}\times\mathbf{c})$. Use parentheses and vector identities carefully
(e.g. BAC–CAB).

**Using Cross in 2D by stuffing Z=0.** It works as a trick to get a scalar z-component, but the
honest type is a scalar or `Bivector2D`, not `Vector3D` pollution in planar code.

**Torque and frames.** Physics $\boldsymbol{\tau} = \mathbf{r}\times\mathbf{F}$ needs a shared
origin; changing the reference point changes $\mathbf{r}$.

## Try it

<details>
<summary>Exercise 1 — Basis check</summary>

What is $(1,0,0)\times(0,1,0)$? $(0,1,0)\times(1,0,0)$?

**Answer.** $(0,0,1)$ and $(0,0,-1)$ — right-hand rule and antisymmetry.
</details>

<details>
<summary>Exercise 2 — Area</summary>

Triangle vertices $(0,0,0)$, $(2,0,0)$, $(0,2,0)$. Area via cross?

**Answer.** $\mathbf{a}=(2,0,0)$, $\mathbf{b}=(0,2,0)$, $\mathbf{a}\times\mathbf{b}=(0,0,4)$,
area $=\tfrac12 \times 4 = 2$.
</details>

<details>
<summary>Exercise 3 — Degeneracy</summary>

`a.Cross(a)` for any `a`?

**Answer.** Zero vector — parallel (identical) inputs.
</details>

## Library recommendations

- **missing-function** — `08-vectors.plato`: `Cross` lives on the intrinsic hub for `Vector3D` but
  is not mentioned on the `Vector` interface or in the `Vector3D` type doc. Surface
  `Cross(Self, Self): Self` in a 3D-only interface (e.g. `CrossProduct3D`) or at least document it on
  the type so readers of `08-vectors.plato` alone discover it.

- **missing-function** — no `Wedge(Vector3D, Vector3D): Bivector3D` dual to `Cross`. The lesson's
  GA nod has nowhere to land; `10-rotations.plato` declares `Bivector3D` without constructors from
  vector pairs.

- **missing-function** — no `ScalarTriple(a,b,c): Number` or `AreParallel(a,b, eps)` helpers.
  Volume and degeneracy checks are the first two call sites after "what is Cross," and both are
  currently handwritten.

- **doc-comment** — `Bivector3D`: document the dual relationship to `Vector3D` cross products
  (component pairing `YZ/ZX/XY` ↔ `(X,Y,Z)` of the cross) under the right-hand convention shared
  with `AxisAngle`. Without that, rotations and vector algebra feel like unrelated dialects.

- **pedagogy** — `Vector2D` lacks a named `Perp` / `Orthogonal` / signed-area helper
  (`a.X*b.Y - a.Y*b.X`). 2D code then either invents one or lifts to fake 3D crosses; a small
  planar primitive would keep the "why only 3D" story honest in APIs.
