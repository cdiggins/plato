# Plato command line

This executable is the command-line front door for developers compiling Plato libraries or running their laws. `Program.cs` routes commands; `GenerateCommand.cs` validates generation options and selects a writer, `LintCommand.cs` reports lint findings, and `RunCommand.cs` handles execution and reports law verdicts. `GenerationArguments.cs` defines accepted generation flags; unknown and retired spellings fail before source loading. Generation and linting share `SourceFiles.cs` for ordered, nonrecursive input discovery. `GeneratedFiles.cs` owns persistence of emitted files, so backends share one writing policy. `Document.cs` holds parser state for compiler inputs, and `Config.cs` supplies standalone defaults.

From the repository root, `dotnet run --project src/Plato.CLI -c Release -- lint stdlib/foundation --strict` parses and resolves a tier without generating output. The project targets .NET 8. See the [agent command guide](../../docs/plato-for-agents.md) for generation commands and exit-code limits, and the [interpreter guide](../../docs/interpreter.md) for law execution. Backend support differs; a successful generation exit does not establish that every body lowered successfully.

The compiler and law suites under [tests](../../tests) exercise this entry point's dependencies. Gate results belong in the [gate log](../../docs/gate-log.md). Report issues through the repository [tracker](../../tracker/readme.md).

After building, run `python tools/check-cli-behavior.py` to exercise generation targets, combined input roots, and error exits. Pass `--baseline <previous-Plato.CLI.dll>` to compare diagnostics and generated content with an older build; only creation-time banner lines are excluded from that comparison. The check uses temporary source fixtures and does not regenerate the standard library.
