`ImplicitCastsMatchBaseline` and `EmittedConversionsMatchBaseline` fail against their committed inventories. Replaying both tests with the original `876fe36b` Plato assemblies and with the repo-468 organization changes produces identical failure messages. The organization work preserved the inventory test files beside their source-relative baselines.

The tests intentionally require semantic review before accepting new coercions. Inspect the actual conversion additions/removals against `stdlib/CONVENTIONS.md` and the single-field wrapping contract, then correct generation or refresh the reviewed inventories. Do not refresh them merely to turn the organization gate green. Both failures obstruct use of the full compiler suite as a clean regression signal.

## Reviewed resolution

No compiler behavior change is needed. The declarations added after the previous inventories satisfy the existing conversion rules:

- `PlacedSdf2D`/`PlacedSdf3D`, `StrutSdf3D`, `GradedStrutSdf3D`, `TpmsNetwork3D` and `TpmsSheet3D` lift to their dimension's `FunctionSdf` and `ScalarFunctionField`. Each existing body captures the same `self.Eval(p)` oracle, preserving the placed transform/scale without sampling or inventing defaults. These are representation changes permitted by `CONVENTIONS.md`.
- `TpmsField3D` lifts only to `ScalarFunctionField3D`; it is not a distance field and gains no SDF conversion.
- `BoySurface`, `CrossCap` and `RomanSurface` each unwrap their sole `Number` field, with the corresponding emitted `NumberValue` bridge. `WhitneyUmbrella` unwraps its sole `Bounds2D`. These are the existing single-field rule, not new inbound wrapping or cross-unit casts.
- `Motor3D` to `AffineTransform3D` keeps the same conversion; its parameter spelling changes from `m` to `x` because the inherited `IRigid3D` function supplies it.

The unchanged `NumberValue` entries were moved from an appended block to the ordinal order generated by the test. Both inventory tests passed in the focused compiler run; no update environment variables were set, and no accepted conversion was removed to hide a failure.
