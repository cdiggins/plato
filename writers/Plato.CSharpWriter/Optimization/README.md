# Writer optimization

These passes rewrite typed intermediate representation (typed IR) before a backend renders source. `CSharpWriter.RunOptimizerPasses` schedules the C# pipeline; the [pipeline reference](../../../docs/csharp-optimizer-pipeline.md) defines pass order, flags, and runtime contracts.

`TirInliner` substitutes resolved callee bodies through the `ITirInlineHost` contract, with refusals recorded by `InlineReport`. `TirComponentUnroller` uses the operation patterns in `ComponentUnroller` to replace fixed-component combinators. `TirArrayMaterializer` handles materialization boundaries. `TirFusion` and `TirLiteralUnroller` simplify compatible chains and literal inputs; `TirLoopLowerer` creates markers rendered by `TirCSharpBodyWriter.Loops.cs`. `TirRewrite` supplies shared tree rebuilding and substitution.

These files retain the `Ara3D.Geometry.CSharpWriter` namespace because other backends consume the shared inliner. Emission syntax belongs in the body writers, while changes to pass semantics require the existing optimizer tests under [PlatoTests](../../../tests/PlatoTests/README.md).

## In-place array updates (`--in-place`, TKT-1132)

`TirInPlaceUpdates` (decisions in `TirUpdateFlow`, marker `TirInPlaceSet`) is the last pass, after `TirLoopLowerer`. Plato arrays are values: `xs.SetAt(i, v)` (`Primitives.SetAt` in the foundation) means a new array, and the emitted C# copies all of `xs`. When nothing can observe the old array afterwards, the pass prints `Intrinsics.SetAtInPlace(xs, i, v)` instead: one element is written into `xs` itself and the same array comes back. The source and the interpreter are untouched, so a law that passes in both engines checks every proof. The helper writes only when the list is a `T[]` and copies any other list, so a proof decides whether a copy is saved and never whether the result is right. An index outside the array changes nothing, as in the Plato body.

### The rule

A `SetAt` call is written in place when all of these hold, and is a copy otherwise.

1. **The callee is the foundation's.** Identified by its declaring library (`Primitives`) and signature, not by the name; the call is not inside a lambda (a loop callback included) or a node the pass does not know.
2. **The receiver is new, made in this body.** Either an expression that builds a new array (an array literal; the temporary of a lowered array loop referenced once; a call to `MapRange`, `Map`, `Append`, `Prepend`, `Concatenate`, `Repeat`, or another `SetAt`), or a local variable every value of which is new: declared once, by a binding whose value is new, and assigned only new values. A parameter belongs to the caller. An array read from a record field, returned by any other call, or chosen by a conditional is not known to be new.
3. **Nothing else holds it.** The variable is not named inside a lambda other than a loop callback (a closure can outlive the statement). Each of its other uses is a borrow (`Count`, `At`, or the source of a lowered loop: they read and keep nothing), the receiver of another `SetAt`, or an escape (bound to another name, passed to any other call, put in a constructor or array literal, returned, assigned elsewhere). An escape must come strictly after the statement that holds the update and must share no loop with it unless the loop also contains the declaration; otherwise the holder would see the write.
4. **The old value has no later use.** In the threaded form, a statement `xs = xs.SetAt(...)`, the variable holds the new version afterwards, so reads of `xs` anywhere are reads of the new array. In any other form (`var ys = xs.SetAt(...)`, a return, an argument) every other use of `xs` must finish before the update runs, and the update must lie in no loop that does not also contain the declaration, because the next pass of such a loop would read what the first wrote.

Statements and the branches of an `if` are taken in the order they are written; a use in the other branch counts as after. That only turns a proof into a copy.

### What it leaves alone

An array that arrives from a caller or a call, or sits in a record, is copied: knowing it is unshared needs ownership across calls, the second criterion of TKT-1132. `Append` and `Prepend` build a longer array and are not updates; an append threaded through a loop needs a presized `List` first (TKT-1131). Updates inside lambdas are not rewritten.

## Owned array storage (`--owned-arrays`, TKT-1152)

`TirStorageResolver` runs at the body writer's entry, after the capture rewrite, and `StorageChecker` verifies what it did before anything prints (the contract is in `ArrayStorage`, `StoragePlan`, `TirRepresent`, `TirStorageScope`). The temporary of a lowered array loop that fills its own `T[]`, is declared once and is never updated in place gets Heap storage: it is declared `T[]`, and `Count` and `At` on it, and a lowered loop reading it, print `x.Length` and `x[i]` with no type test. Every other consumer of such a temporary receives it through a `TirRepresent(Heap -> List)`, printed as a cast to the interface, so a `Reduce` seed, a `FlatMap` source, a conditional arm, a return and a call argument compile as before. The resolver decides which references are readers and which need the conversion; the printer reads `StoragePlan.Of(node)` and decides nothing. Anything the plan does not name is List, today's form, so a body the resolver leaves alone prints byte for byte as with the flag off. A named local follows the same rule (C2c): a `var` or lowerer alias whose value is a Heap array, declared once, never assigned again, never updated in place and not named by a printed lambda is itself Heap, declared `T[]`; one that fails a condition stays List with the reason on `StoragePlan.Refusals`. A `FlatMap` source and the source of a paired reduction (`TirMultiReduction`) are loop sources, so they read a Heap array directly, the exact-output form without its `is T[]` test; under `--in-params` an element of a Heap array of large structs is read in place (`ref readonly var w = ref x[i]`, or the element itself as an argument or receiver) instead of through `RefAccess.RefAt`. A node the printer has no case for is a checker refusal (S8), not `/*?*/` in the output (`TirCSharpBodyWriter.PrintsAsNode` lists the classes it prints). Tests: `tests/PlatoTests/Emission/OwnedArrayEmissionTests.cs` (each TKT-505 shape compiled with Roslyn and run) and `tests/Plato.Interpreter.Tests/OwnedArrayProgramTests.cs` (the laws of `OwnedArrayFixtures/owned.plato` and `owned-large.plato`, interpreted and compiled with the flag off and on).

## Stack slots (`--stack-arrays`, TKT-1152 chunk C6)

With `--owned-arrays`, a bounded owned temporary that is only read becomes `ArrayStorage.Stack`: a `Span<T>` over a `stackalloc` slot declared before the outermost lowered loop around its allocation, a heap array when the run-time count exceeds the slot (`min(16, 256 / sizeof(T))` elements), at most 1 KiB of slots per body, no slot in a body on a call cycle (`CSharpStorageTarget.OnCallCycle`). The rules, the refusal reasons and the printed form are in `docs/csharp-optimizer-pipeline.md` section 7h; the checker (S5, S7) re-verifies every plan.

## Shared calls (`--share-calls`, TKT-1136)

`TirSharedCalls` runs before the loop lowerer. A `match` lowers to a chain of tag tests and field reads that each name the scrutinee's expression, so `match (F(x)) { Decoded(row) => ...; Skipped(code, about) => ...; }` called `F` five times in the C# (the machine of the STEP front end decoded every curve and surface row twice on its common path, five times on a skip). A call that one statement evaluates twice returns the same value twice, so the pass evaluates it once into a local declared before the statement.

A call is shared when, inside one statement's expression, a second node has the same callee, emission kind and arguments (variables and parameters by identity, literals by value), and at least one occurrence is evaluated on every path (an operand of a call, constructor or conversion, or the condition of a conditional, never a branch of one). It must be a method call (not a field read, operator, constructor or conversion), of no array type (the loop passes own repeated arrays) and no affine builder type, with no lambda or unknown node below it; the expression must assign nothing. The largest shared call is bound first and the rest are searched again, so a shared argument gets its own local before the call that reads it. A lambda body is another expression and is not entered; one statement is the unit, so `var a = F(x); var b = F(x);` shares nothing.

Tests: `tests/PlatoTests/Optimization/SharedCallsTests.cs` (the tree of each case of `SharedCallsFixtures/shared-calls.plato`: seven shared, four kept) and `tests/Plato.Interpreter.Tests/SharedCallsProgramTests.cs` (the fixture's laws interpreted and compiled with the flag off and on, equal verdicts, and the calls of `Cost`, `Row` and `Make` counted in the IL).

## Decoder-wave rewrites (TKT-1138, TKT-1142)

Three pure optimizations that make plainly written Plato fast, each behind its own switch and each off by default (the output with the switches off is byte-identical to the output before them). The first two run on the TIR as the elaborator builds it (`ElaborationOptions`, passed by `TirEmitSource` and by the `Interpreter`), so the interpreter takes them too and the two engines keep agreeing; sinking runs again in the C# writer after inlining. The third is a part of the shared-calls pass.

### Match scrutinee bound once (`--bind-scrutinee`, TKT-1138)

`src/Plato.Compiler/Checking/TirScrutineeBinding.cs`. `ElaborateMatch` records the node its tag tests and field reads all hold; after the function is elaborated, a scrutinee that is not a variable, parameter, literal or field read of one is bound to `var _scrutN = E;` before the statement that holds the match, and every occurrence reads the local. Limits: the scrutinee must be evaluated on every path through the statement's expression (not in an arm of a conditional or of another match, not under a lambda), and the expression must assign nothing; the statements reached are the returns, locals and `if` conditions of the body's blocks and `if` branches, and a body that is one expression becomes a block ending in a return. Nested scrutinees (a match inside a scrutinee) are bound innermost first. With `--share-calls` on the compiled code of a match on a call is the same either way; the gain is in the interpreter and in C++ or any writer without the pass.

### Sink pure bindings (`--sink-bindings`, TKT-1142)

`src/Plato.Compiler/Checking/TirSinkBindings.cs`, then `TirSinkBindingsPass` after inlining. A `var x = <expr>` whose only reader is one arm of a conditional is evaluated on that arm: moved into the one branch of an `if` that reads it; substituted for its single read when that read is under an arm of a conditional expression (`c ? a : (d ? basis : k)`); and, when an arm reads it more than once or inside a lambda, the `return` of the conditional becomes an `if` whose arm declares the local. Locals chain (a local that only a sunk local reads moves too). Kept: a read in a condition or outside every conditional, reads in two statements or both arms, a value that is a variable, literal, lambda or has an affine builder type, a name declared twice in the function, and any function that assigns or loops. Sinking only removes evaluation, so a local whose evaluation would fail or not terminate no longer does when no path reads it; the interpreter runs the same pass under the same switch, so both engines agree (a run with the switch off keeps the old behaviour in both). Sinking before sharing can hide a share: `var a = F(n); return c ? F(n) + a : 0;` becomes `c ? F(n) + F(n) : 0`, two calls on one arm, which costs no more than before.

### Wide call sharing (`--share-calls-wide`, TKT-1142, needs `--share-calls`)

`TirSharedCalls`. Three extensions, all on the same rule (a call is shared only when an occurrence is evaluated on every path, so evaluating it first adds no work): a call that one statement of a block evaluates on every path and that a later statement of the block names again, in any position and under a lambda, is bound once before the first statement (its arguments must be function parameters or locals declared before it); the call of a lambda body that the body repeats is bound once inside the body, which becomes a block when it needs the local; and a sum case written as a factory (`Kind.EdgeLoop`) is part of a call's identity, which is what lets `FrontEndF8Is(p, EdgeLoop())` match itself.

Tests: `tests/PlatoTests/Optimization/DecoderRewriteTests.cs` (the tree of each case of `DecoderRewriteFixtures/rewrites.plato`) and `tests/Plato.Interpreter.Tests/DecoderRewriteProgramTests.cs` (the fixture's laws interpreted and compiled with the switches off and on, equal verdicts, the interpreter's evaluations of `Cost` and `Row` counted, and the IL call sites).

## Closure-free arrays (`--closure-free`, TKT-1149)

Two costs the STEP decoder's profile found in the stdlib's array functions. `Append`, `Prepend`, `Concatenate`, `Take`, `Skip` and the like are each a `MapRange` whose callback picks a source element, and a generic C# body cannot be loop-lowered (its element type is a type variable), so every call allocated a closure and called a `Func` once per element (11 percent of a decode inclusive, 8 percent exclusive in `MapRange`). `Sort` and `SortedIndices` called their comparator through a `Func` on every compare.

**Copy-shaped functions** (`ClosureFreeArrays.cs`). With the flag on, the extension for `Append`, `Prepend`, `SetAt`, `Concatenate`, `Take`, `Skip`, `TakeLast`, `SubArray` and `Slice` of the `Primitives` library is written as one call to `ClosureFreeArrays` (a generated file, `ClosureFreeArrays.g.cs`): one allocation of the result and `Array.Copy` (or `List<T>.CopyTo`, or an indexed loop for another list). The Plato bodies stay the definition; the interpreter runs them. The choice of an intrinsic over teaching the loop lowerer to recognise the `MapRange` bodies: the lowerer works at a call site and needs a concrete element type, and a function matched by what it is (library, name, parameter types) cannot drift when a body is reworded. Edge cases are the `MapRange`'s: a count of zero or less is the empty array, and a window outside the source (a precondition in the library) is read element by element as before, so it throws the same exception at the same element.

**Sorting** (`TirLoopLowerer`, kinds `Sort` and `SortIdx`, needs `--loops`). A call of `Sorting.Sort` or `SortedIndices` whose result element type is a concrete C# type is lowered to the library's bottom-up merge sort over an index permutation, written in the caller with the comparator lambda inlined as the merge's test. The comparisons are the same, in the same order, with the left run winning ties, so the order is the library's (the fixture's laws pin ties). A comparator that is a function value (a delegate-typed parameter or variable) is still called through the delegate but from the inlined loop. A `Sort` inside a generic body (element type a type variable) stays a call.

Tests: `tests/Plato.Interpreter.Tests/ClosureFreeProgramTests.cs` over `tests/PlatoTests/Optimization/ClosureFreeFixtures/closure-free.plato` (the laws interpreted and compiled with the flag off and on, equal verdicts; the IL of each extension and of each sort call site; faults of out-of-range windows). The C++ Cpu prelude already writes `Append`, `Concatenate` and `Prepend` as loops into an arena array, `Take`, `Skip` and `Slice` as views, and the C++ backend passes comparators as template arguments, so the switch applies to C# only.

## More loops (`--lower-more`, lambda removal L3)

In the STEP mesher's generated C# (`--loops` and the eighteen other switches on), 94 `MakeArray2D` call sites still built a delegate: 73 of them the grid builders in `Meshes.g.cs` (`nCols.MakeArray2D(nRows, (col, row) => ...)`, the mesh assembly path) and the B-spline control-point grids. The stdlib body wraps `f` in a second lambda for its `MapRange` (`MapRange(columns * rows, i => f(i % columns, i / columns))`), so the plain lowering can reach the inner lambda only inside the generic body, where the element type is a type variable. Each surviving lambda is a delegate allocation and an indirect call per cell.

**The switch** (`CSharpWriter.LowerMore`, `LoopOptimizationOptions.LowerMore`, needs `--loops`, C# only, default off) adds four kinds to `TirLoopLowerer`, printed by `TirCSharpBodyWriter.Loops.cs`: `Make2D` (`Primitives.MakeArray2D`), `Make3D` (`MakeArray3D`), `Cartesian` (`CartesianProduct`) and `Filter`. A grid is one `new T[cols * rows]` (times `layers`) filled row-major by nested loops with the callback's parameters bound to the loop counters and a running element index, then the `Array2D<T>` or `Array3D<T>` record built once; a non-positive extent means no cell, and the record keeps the extents as given (the only difference from the stdlib body is the ill-formed call with every extent negative, whose `MapRange` count is positive: lowered, the grid is empty). `Filter` fills an array presized to the source's count and trims it with one `Array.Resize` when fewer elements pass, so the common case allocates once; its receiver may be a fused producer chain like `Map`'s. The refusals are the lowerer's: the element type and, for a grid, the record type must be concrete C# types (a generic body keeps its call), the callback a literal lambda or a `Function{N}` value of the arity, and the callee the `Primitives` function. `TirLoopInvariantHoister` handles the new loops like any lambda-callback loop (its locals sit inside `if (n > 0)` around the loop nest); `--presize` is unaffected. Off, the output is byte-identical. On the mesher, every `MakeArray2D` lambda site is gone (2,663 lambdas to 2,558); the two `FlatMap` lambdas that remain are the generic bodies of `Filter` and `Flatten` in `Extensions.g.cs`.

Tests: `tests/PlatoTests/Optimization/LowerMoreTests.cs` over `LowerMoreFixtures/lowermore.plato` (each kind compiled and executed on and off: same values, same callback order, zero and negative extents; the hoist interaction on an empty grid; the type-variable refusal; the switch-off text).

## Scalar arrays (`--scalar-arrays`, TKT-1152 chunk C0)

`ComponentArray(v)` of a `Vector3D` allocated a `Number[3]` and its consumers (`SumSqrComponents`, `MinComponent`, `MapComponents`, `ZipComponents`, `Dot`-like folds) looped over it: about a fifth of the face stage's allocated bytes in the STEP mesher's `NumericStructures`. **The switch** (`CSharpWriter.ScalarArrays`, `LoopOptimizationOptions.ScalarArrays`, C# only, default off, useful with `--fuse`) adds `ConstantCounts`, a TIR rewrite before `TirFusion`: the constant `Count` of a fixed-arity struct (the writer's synthesized `Count`: a concrete struct of two or more fields, not a primitive, no `Count` or `At` of its own) folds to a literal; a combinator over `ComponentArray(v)` unrolls over the array of component reads `v.X, v.Y, v.Z` through the policy-taking rules of `TirLiteralUnroller` (a component read may repeat, a delegate combiner is invoked per element, a twice-read `Reduce` accumulator may repeat under a 128-node budget); and `FromComponents(v, [a, b, c])` of the matching arity becomes `new T(a, b, c)`. Only a leaf receiver is folded or repeated, so no fault is dropped; element `j` is computed before element `j + 1`, so callbacks run in the loops' order. A refused unroll keeps the call. Off, the output is byte-identical. Section 7f of `docs/csharp-optimizer-pipeline.md` has the rules and the interactions.

Tests: `tests/PlatoTests/Optimization/ScalarArraysTests.cs` (emitted text of the library bodies, clones and probes with the nineteen pinned switches plus `--fuse`, flag off and on) and `tests/Plato.Interpreter.Tests/ScalarArraysProgramTests.cs` over `ScalarArraysFixtures/scalar-arrays.plato` (the whole program compiled with the flag off and on: bit-equal results over finite, signed-zero, NaN and infinite vectors, the order of callback calls, a callback that throws, and the laws in the interpreter and both compiled arms).
